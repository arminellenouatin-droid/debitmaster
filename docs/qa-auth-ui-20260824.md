# Vérification UI auth — 24 août 2026

Le parcours `/inscription` local répond en HTTP 200 et affiche une carte en deux colonnes sur desktop avec les éléments « Propriétaire » et « Membre d’équipe ». Le mode propriétaire visible comprend prénom, nom, téléphone, e-mail professionnel et mot de passe.

Le premier clic navigateur sur « Membre d’équipe » n’a pas modifié l’état visuel : la page affichée reste en mode propriétaire. Ce point doit être revérifié avec une interaction DOM plus directe ou avec le test du formulaire en navigateur. Le build et TypeScript passent cependant avec l’environnement de production.

Le test `POST /api/auth/login` avec un téléphone fictif et un mauvais mot de passe répond HTTP 401, sans divulguer de détail sensible.


Après redémarrage du serveur et ouverture via `localhost`, le clic sur « Membre d’équipe » fonctionne. Le formulaire affiche alors prénom, nom, téléphone, code établissement, poste, mot de passe et le bouton « Demander l’accès », sans champ e-mail. Le test visuel confirme donc le parcours attendu sur desktop. Le formulaire est à tester sur mobile avant livraison finale.
